# 03 · 定址（自動定址，取代指撥開關）

> ⚠️ **2026-10-13 定案（[06 §O](06_設計決策與待確認.md)）：手動指撥開關(DIP)全拿掉，改拓樸自動定址。** 本文原為 7-DIP 定址，現改述自動定址；機制細節在 [10 §8](10_自動終端與拓樸.md)。保留字串路徑/逐跳前綴模型（§3）不變。

## 1. 自動定址（ENUM 枚舉）取代 DIP

節點**不再用指撥設定位址**，而是靠與上/下/同層鄰居的通訊**自我定位**：「沒有上層就沒有下層、沒有同層前一台就沒有同層下一台」。換板後短時間內自動復位。

- **騎在 daisy-chain 上**：A/B、電源、`ENUM` 線走**同一組 in/out 連接器、同順序**串接（[10 §4/§8](10_自動終端與拓樸.md)）。
- **枚舉**：每條 bus 的 master（中繼器該埠）點名，只有 `ENUM_IN` 有效且未定址者回應、領**本地鏈序**（1,2,3…），領到後拉 `ENUM_OUT` 放行下一台，直到鏈尾。
- **本地位址 = 實體鏈序**（1–63，0 保留廣播）；**全路徑 = 父層 path + 本地鏈序**（見 §3）。
- **衝突不可能**：序號由 master 單一來源依序發。
- **換板**：新板上電為未定址 → 重枚舉 → 依鏈序復位同位址，上層無感。

> 好處＝客戶「插上即用」：不必撥任何開關、不會撥錯、不會撞址；壞了直接換同款模組，自動回到原位。

> ⚠️ **2026-11-01 精修（EZ_IO）：編號/身分一律以 JSON 為主**（identity，不依物理位置——23 號旁邊可以是 31 號）。ENUM 枚舉負責**探索鏈上設備與物理順序 + 自動終端**，但使用者看到的**編號／身分對照 JSON/型錄**、跟著設備走。見 [06 §O-2](06_設計決策與待確認.md)、[ez_io_design_notes](ez_io_design_notes.md)。

## 2. 常規 vs 進階（編輯）模式 — 改軟體指令

原本「DIP 功能位 ON=常規 / OFF=進階」隨 DIP 一起拿掉，改為**軟體指令切換**：

| 模式 | 觸發 | 行為 |
|------|------|------|
| **常規** | 預設 | 末端：被輪詢回量測值。中繼器：輪詢下層+回 cache。 |
| **進階/編輯** | 軟體指令（如 `CFG|<addr>`，見 [02 §6](02_通訊協定.md)） | 進設定模式：更新自有 JSON、校正、參數；用位址精準指定某台。 |

呼應記憶 `firmware-soft-reset`「不加實體腳、靠軟體指令（位址 N → 重開 / CFG）+ 看門狗」的方向。進階模式用於**部署前預配**或**現場維修**。

## 3. 分層位址：字串路徑（不變）

分層位址用**字串**表示，例如 `1-32-4`：

| 段 | 意義 |
|----|------|
| `1` | 第 1 層、該 bus 上鏈序 1 的中繼器 |
| `32` | 第 2 層、該中繼器底下鏈序 32 的中繼器 |
| `4` | 第 3 層、該中繼器底下鏈序 4 的設備（末端） |

**為什麼用字串不用陣列**（[需求 4]）：陣列要預先開固定維度，層數/數量一多就位址不足或浪費。字串路徑可任意長任意寬、動態成長不受限。

> **路徑只到「節點」（中繼器＋末端），不含外設**（2026-09-16 定案）：末端底下的外設**不進樹狀定址**——末端 MCU 自己用 MODBUS(@115200) 或其他尾段協定去抓外設、放進本地 cache，靠 descriptor 索引。所以最深段是**末端節點**（如 `1-32-4`），不是外設。要某外設的值＝向該末端節點 REQ，由它從 cache 提供。詳見 [02 §3.1](02_通訊協定.md)、[08](08_末端外設_Driver_韌性架構.md)、[06 §N](06_設計決策與待確認.md)。

### 3.1 逐跳前綴（路徑怎麼長出來）

每台設備**只知道自己的本地鏈序**（自動定址給的）。完整路徑在資料**往上流**時，由每台中繼器**前綴自己的本地位址**拼出來：

```
末端(鏈序=4)          送: "4|…"
  → 中繼器(鏈序=32)   前綴 → "32-4|…"
    → 中繼器(鏈序=1)  前綴 → "1-32-4|…"
      → PC 收到完整路徑 1-32-4
```

- 末端不需要知道自己在第幾層，只管報本地鏈序。
- 中繼器只做一件事：把收到的孩子資料，前面接上 `自己的本地位址 + "-"`。

### 3.2 設備怎麼知道自己在第幾層

自動定址本身就給了答案：**沒有上層就沒有下層**——節點由上游枚舉鏈得知深度，由同層 `ENUM` 鏈得知同層順序（[10 §8.3](10_自動終端與拓樸.md)）。絕對層數主要用於顯示/診斷。

## 4. JSON 與設備身分

- **末端**：各自存一份**自有設備 descriptor（JSON）**（型別、型號、單位、量程、校正、外設抓取方式…）。
- **中繼器**：存**型錄（所有已知 descriptor 的庫）**，辨識/驗證下層、支援 hot-swap。
- **熱替換**（[需求 16]）：descriptor 可預載進中繼器、位址又自動產生 → 維修時**換上同款模組即可**（免撥開關、自動定位、型錄推設定），上層無感。比舊 DIP 版更好用。
