# 03 · 定址與指撥開關

## 1. 7 階指撥開關配置

每台設備（中繼器與末端傳感器都一樣）用一顆 **7 位 DIP switch**：

```
位  7   6   5   4   3   2   1
   [ 位 址  0 – 63  (6 bit) ]   [ 功能 ]
    MSB ─────────────► LSB       ↑
                                 第 1 階
```

| 欄位 | 位數 | 用途 |
|------|------|------|
| **位址** | 6 bit（位 2–7） | 本設備在**所屬那條 bus** 上的本地位址，0–63 |
| **功能** | 1 bit（位 1） | **ON＝常規操作**（向下讀取/回報）；**OFF＝進階操作**（編輯此設備，如寫 JSON/設參數） |

- 6 bit → 64 個位址，正好對應「一條 bus 最多 64 台」。
- 功能位的語意（[需求 2]）：**開(ON)=常規、關(OFF)=進階編輯**。
- 位址「所屬那條 bus」是關鍵：同一個本地位址 `4` 在不同分支底下是不同設備，靠上層路徑前綴區分（見 §3）。

### 建議：保留位址 0 當廣播/未設定

6 bit 原始是 0–63。建議 **0 保留給廣播 / 未配置**，實際可用 **1–63（63 台）**。若你堅持要塞滿 64 台，就得另想廣播機制。此點列入 [06 待確認](06_設計決策與待確認.md)，預設採「0 保留」。

## 2. 常規 vs 進階（功能位）

| 功能位 | 模式 | 行為 |
|--------|------|------|
| **ON** | 常規 | 末端：被輪詢就回量測值。中繼器：正常輪詢下層+回 cache 給上層。 |
| **OFF** | 進階/編輯 | 該設備進入設定模式，接受寫入：更新自有 JSON、校正參數、位址相關設定等。 |

進階模式用於**部署前預配**或**現場維修**。指令格式見 [02 §6](02_通訊協定.md)。

## 3. 分層位址：字串路徑（不是陣列）

分層位址用**字串**表示，例如 `1-32-4`：

| 段 | 意義 |
|----|------|
| `1` | 第 1 層、第 1 台中繼器（最靠近 PC 那條 bus 上的本地位址） |
| `32` | 第 2 層、該中繼器底下第 32 台中繼器 |
| `4` | 第 3 層、該中繼器底下第 4 台設備（末端） |

**為什麼用字串不用陣列**（[需求 4]）：陣列要預先開固定維度/大小，層數或每層數量一多就會位址不足或浪費。字串路徑可任意長、任意寬，動態成長不受限。

### 3.1 逐跳前綴（路徑怎麼長出來）

每台設備**只知道自己的本地位址**（指撥值）。完整路徑在資料**往上流**時，由每台中繼器**前綴自己的本地位址**拼出來：

```
末端(指撥=4)          送: "4|{...}"
  → 中繼器(指撥=32)   前綴 → "32-4|{...}"
    → 中繼器(指撥=1)  前綴 → "1-32-4|{...}"
      → PC 收到完整路徑 1-32-4
```

- 末端不需要知道自己在第幾層，只管報本地位址。
- 中繼器只需做一件事：把收到的孩子資料，前面接上 `自己的本地位址 + "-"`。

### 3.2 設備怎麼知道自己在第幾層（[需求 9]）

一台設備裝上去後，可由兩個線索得知自己的深度：

1. **上層要求裡帶的路徑深度**：上層來要它時，用的位址前綴長度＝它上面有幾層。
2. **下層回來的資料**：若它有收到下層孩子的資料 → 它是中繼器（非葉）；若沒有下層 → 它是末端。

實務上，**大多數運作不需要設備知道絕對層數**——它只要「知道本地位址、會前綴、會輪詢下層」即可正常運作。層數主要用於顯示/診斷。此點的嚴格定義列入 [06](06_設計決策與待確認.md)。

## 4. JSON 與設備身分

- **末端傳感器**：各自存一份**自有設備 JSON**（型別、型號、單位、量程、校正、暫存器對應…）。
- **中繼器**：存**所有已知設備 JSON 的庫**，用來辨識/驗證下層回報的是哪種設備。
- **熱替換動機**（[需求 16]）：因為 JSON 可預載進中繼器、位址又靠指撥，維修時把新中繼器預載好所有 JSON、撥成相同位址，插上去即可接手，上層無感。
