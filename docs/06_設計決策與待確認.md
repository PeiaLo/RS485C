## G. WiFi / 距離（新增 · 待你討論）

> 你的疑問：末端距離較遠是否要用 WiFi？中間層需不需要 WiFi？

**先破一個迷思：RS485 本身就很適合長距離**。它是差動匯流排，低 baud 下可拉到約 **1200 公尺**。所以「單純距離遠」通常**直接拉 RS485 線就好，不需要 WiFi**。

WiFi 在這套系統只有**兩個真正的用途**，而且是「**替換某一段連結**」，不是每層都要：

1. **頂層對 PC 的頻寬紓解**（你的點 11）：樹很大時，PC 端 RS485 接收會排隊 → 讓「頂層中繼器 ↔ PC」這一段改走 WiFi/Ethernet（ESP32 內建 WiFi 最省事）。樹內部仍走 RS485。
2. **拉不了線的物理斷點**：某個分支在**另一棟廠房 / 會旋轉或移動的設備**上，纜線過不去 → 在那個分支點放一台「**WiFi 橋接中繼器**」，把**那一段連結**從 RS485 換成 WiFi。

**關鍵好處**：因為 `\n`/`\r` 框架和位址系統**與傳輸媒介無關**，WiFi 只是把某段連結的 bytes 改用 TCP/UDP 送，**協定、定址、cache 邏輯完全不變**——這正是[模組 F 傳輸層抽象](04_軟體模組拆分.md)要做的事。一台 ESP32 同時有 WiFi + RS485，所以「橋接中繼器」＝一台 ESP32：下層 RS485、上層 WiFi。

**中間層需不需要 WiFi？** 預設**不需要**。中間層走 RS485 又快又穩又便宜。只在「①頂層對 PC」或「②某個拉不了線的分支」才點名用 WiFi。

**取捨提醒**：WiFi 有延遲/抖動、要處理斷線重連，不像 RS485 那麼即時可預期；工廠可靠度優先，能拉線就拉線，WiFi 當「跨不過去時的橋」。好在 cache 樹在這裡幫大忙——WiFi 橋接的子樹即使斷線也還在本地輪詢+快取，重連後直接把 cache 給上去。

**待你決定**：目前是否已有「跨棟 / 移動設備 / 頻寬爆掉」任一情境？沒有的話，**先全走 RS485**，把模組 F 的 `Link` 介面留好接口即可，等真的遇到再插 WiFi 實作。

## H. 拓樸韌性 / 前端冗餘（定案 2026-08-19）

### H0. 容量與兩道「牆」
- **定址**：每 bus 64 位址、保留 1（廣播/其他功能）→ **63 可用**；分層字串位址長度不限 → 定址幾乎無上限，最大末端 = **63^D**（D=bus 層數）。
- 真正的上限**不是定址**，是：
  - **牆 A｜頂層頻寬（限制總設備數）**：PC 拉整包 cache 時，頂層鏈路要吐「全部末端」。純有線 MAX13487(500kbps) ≈ 1,250 筆/秒 → 秒級整包刷新的實務天花板**約 2 層（數千台）**。要更大 → PC 改「要指定位址」不拉整包，或頂層換 Ethernet/WiFi（模組 F）。
  - **牆 B｜端到端新鮮度延遲（限制層數）**：cache 讓各層解耦，葉端新鮮度 ≈ 自己那條 bus 一圈；新值「冒到 PC」≈ 層數 × 一圈。高 baud 下層數牆很寬，通常先撞牆 A。
- 計算/驗證腳本：`sim/capacity.py`（63^D 表）、`sim/link_budget.py`（頻率/延遲/牆）、`sim/simulate.py`（走真實 `lib/protocol.py` 的資料流模擬）。

### H1. 分層韌性策略（依故障半徑分配冗餘）
- **看門狗（全體，零硬體成本）**：每台 ESP32 開硬體 watchdog，韌體卡死/暫態自動重開——CP 值最高的一招。
- **溫備援（多數節點）**：預載 JSON、撥同址、壞了插上頂替；搭配 **PC 端新鮮度告警**（cache 帶時戳、過期標紅）讓人及時換。用於故障半徑小的葉端。
- **熱備（只押頂層 1~2 層）**：故障半徑最大的節點才上自動 failover。

### H2. 前端中繼器（PC 下那台）＝熱備
本系統**唯一的全樹單點**，冗餘預算優先押這裡。

- **熱備機制**：主+備兩台；備機平時**被動偷聽第 1 層 bus** 保溫 cache；PC 連續 N 次逾時 → **PC 當仲裁**點名備機接手、備機升為第 1 層 master。仲裁權在 PC → 不會雙主。
- **上行（PC ↔ 前端）＝兩條點對點快速 RS485（選項 A，定案）**：
  - ESP32 端用帶方向控制的快速收發器（THVD1450 / MAX3485 級，多 Mbps），PC 端用 USB-RS485 轉接頭；**每台一條獨立 P2P 線**。
  - 好處：速度比 MAX13487 快 ~10×（把牆 A 外推一級）＋兩條獨立線＝**PC 側鏈路也冗餘**＋PC 對兩台獨立問，split-brain 最單純。
  - **刻意偏離全系統「免 DE/RE」慣例**：此鏈路為求速度採方向控制；因點對點只有兩端、轉向時序最單純，可接受。其餘 multidrop bus 仍用 MAX13487。
- **下行（後端）＝主+備共掛同一條第 1 層 bus**：
  - 後端**零複製**：兩台的下行收發器（MAX13487）接同一對 A/B 線，都只是這條 bus 上的 drop。
  - **master 不佔位址** → 第 1 層 bus 仍 **63 台**孩子。（註：若改用「主機把備機當心跳孩子輪詢」的做法才會 −1 = 62；本設計用「偷聽 + PC 仲裁」，維持 63。）
  - **防撞線**：同時只有一台在發；備機被提升前，對第 1 層 bus 的 UART **保持靜默**（MAX13487 AutoDirection：不發即不驅動匯流排）。
- **已知缺口**：第 1 層 bus 的**共享纜線本身仍是單點**（斷線則斷點後全失聯）。要連纜線也保護需環網 / 雙 bus，**暫不做**，先標記。
