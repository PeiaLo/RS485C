# 05 · 測試架構建議

用你手上的硬體，**分階段**驗證，先跑通兩顆節點、再長成樹。

## 手上硬體與角色分配

| 硬體 | 邏輯準位 | 建議角色 |
|------|----------|----------|
| **Arduino UNO** | 5V | 末端傳感器（模組 A）。5V 好配 MAX13487。 |
| **ESP32** | 3.3V | 中繼器（模組 B，MicroPython）；也可當末端 |
| **Nucleo（F401RE 等）** | 3.3V（IO 5V 容忍） | 額外末端 / 或異質 slave，測相容性 |
| **STM32（裸板）** | 3.3V | 額外末端節點 |
| **MAX13487** | **VCC = 5V** | RS485 收發器（AutoDirection） |

> ⚠️ **混壓提醒**：MAX13487 是 5V 件。RS485 **差動 bus 混接 3.3V/5V 節點沒問題**（靠差動閾值），但要注意**收發器邏輯腳（DI/RO）對 MCU 的準位**：
> - UNO（5V）↔ MAX13487（5V）：直接接。
> - ESP32/STM32（3.3V）↔ MAX13487（5V）：MAX13487 的 RO 輸出高電位約 VCC，**餵給 3.3V MCU 的 RX 可能超壓** → 建議 RO→MCU 之間分壓或用準位轉換；DI 端 3.3V 通常可達 MAX13487 的 VIH（但請查你手上批號 datasheet 確認 VIH）。
> - 另一選擇：ESP32 側改用 **3.3V RS485 收發器**（如 MAX3485/THVD1450），只在需要 5V 的 UNO 節點用 MAX13487。細節列入 [06](06_設計決策與待確認.md)。

每個 RS485 埠要一顆收發器：**末端 1 顆、中繼器 2 顆（上+下）**。先數好你有幾顆 MAX13487 再排階段。

## Stage 0 — 兩節點點對點（先證框架）

```
[ESP32 中繼器] ──DI/RO── [MAX13487] ══A/B RS485══ [MAX13487] ──DI/RO── [Arduino UNO 末端]
   MicroPython                                                              Arduino
```

- **目標**：驗證 [02 協定](02_通訊協定.md) 的 `\n`/`\r` byte 串流、UNO 讀指撥、`<位址>|<json>\r` 收送。
- **做法**：ESP32 週期性對 UNO（本地位址=4）發要求；UNO 回 `4|{"t":"TMP","v":26.7,...}\r`；ESP32 印出解析結果。
- bus 兩端各 120Ω 終端 + 一處 failsafe 偏壓。
- **過關條件**：連續收送無錯、逾時（拔線）能被偵測。

## Stage 1 — 一台中繼器 + 多末端（單 bus multidrop）

```
[ESP32 中繼器] ══ RS485 bus ══╦══ [UNO 末端 #4  溫度]
                              ╠══ [ESP32 末端 #5 壓力]
                              ╚══ [STM32 末端 #6]
```

- **目標**：round-robin 輪詢、cache dict、逾時跳過。
- **測試**：拔掉 #5 → 中繼器該格標 stale 並繼續輪詢其餘；插回 → 恢復 fresh。
- **過關條件**：cache 內容正確、單一節點失聯不卡住整條 bus。

## Stage 2 — 兩層樹（驗證分層位址 + cache 樹）

```
PC(Python) ══串列══ [ESP32 第1層中繼器 本地=1]
                          ║下層 bus
                 ╔════════╬═════════╗
        [ESP32 第2層中繼器 本地=32]  [UNO 末端 本地=5]
                 ║下層 bus
          [Nucleo/STM32 末端 本地=4]
```

- **目標**：
  - **逐跳前綴**：Nucleo 末端最終在 PC 端顯示為 `1-32-4`。
  - **上要下給**：PC 要資料時，第1層中繼器直接回 cache（不等下層跑完）。
  - PC 儀表板顯示樹狀 + 即時值 + 新鮮度。
- **過關條件**：位址字串正確拼出、PC 讀取速率與下層 bus 解耦（下層照跑、PC 隨要隨有）。

## Stage 3 — PC 規則引擎 +（可選）Ethernet/WiFi 頂層

- PC 端做 [需求 17] 的**條件設定 → 自動控制**（例：某位址溫度 > 門檻 → 對某輸出位址下命令）。
- 若 Stage 2 觀察到 PC 端串列塞車，導入 **模組 F**：頂層 ESP32 對 PC 改走 WiFi/Ethernet（ESP32 內建 WiFi 最省事），對下層仍走 RS485。
- **過關條件**：大量節點下 PC 端不排隊、規則觸發延遲可接受。

## 建議工具

- **邏輯分析儀 / USB 轉 RS485**：直接掛 bus 上抓 `\n`/`\r` 框架，除錯最快。
- **兩顆 USB-TTL**：Stage 0 前可先不接 RS485，用 TTL 直連驗協定，再換上 MAX13487 驗實體層。
- **一致性測試向量**（來自模組 C）：三邊實作都跑同一組向量。

## 階段對應到模組

| Stage | 主要驗證的模組 |
