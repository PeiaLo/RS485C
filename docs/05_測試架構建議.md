# 05 · 測試架構建議

> ✅ **Stage 0–2 已由深鏈 `1-2-3-7` 實機驗通**（3×RP2040 中繼 × 1×STM32 末端，見 [bringup_1237.md](bringup_1237.md)）。本文保留**分階段測試方法**；平台以定案為準：中繼器=**RP2040/MicroPython**、末端=**STM32/C++**（ESP32/UNO 為早期舉例，去陸製排除 ESP32，見 [08 §3](08_末端外設_Driver_韌性架構.md)、[09](09_軟體架構定案.md)）。

用手上硬體，**分階段**驗證，先跑通兩顆節點、再長成樹。

## 硬體與角色分配

| 硬體 | 邏輯準位 | 角色 |
|------|----------|----------|
| **RP2040**（YD-RP2040 / Pico） | 3.3V（非 5V 容忍） | 中繼器（模組 B，MicroPython，雙 UART） |
| **STM32**（F411 / F103 測試） | 3.3V（IO 5V 容忍） | 末端傳感器（模組 A，C++） |
| **RP2040 + W5500** | 3.3V | 高速傳送型中繼器（Ethernet） |
| **MAX13487** | **VCC = 5V** | RS485 收發器（AutoDirection，現行主用） |

> ⚠️ **準位提醒**：MAX13487 是 5V 件。RS485 **差動 bus 混接沒問題**（靠差動閾值），但**收發器 RO → MCU RX** 要注意：
> - **RP2040（非 5V 容忍）**：RO→RX **必須分壓**（1.8k/3.3k，5V→3.24V）。
> - **STM32（FT 腳）**：RO→RX 可直接。
> - 更省事：改用 **3.3V true fail-safe 收發器**（TI THVD2450 / SN65HVD75），免分壓又免偏壓（見 [08 §3.2](08_末端外設_Driver_韌性架構.md)）。

每個 RS485 埠要一顆收發器：**末端 1 顆、中繼器 2 顆（上+下）**。

## Stage 0 — 兩節點點對點（先證框架）

```
[RP2040 中繼器] ──DI/RO── [MAX13487] ══A/B RS485══ [MAX13487] ──DI/RO── [STM32 末端]
   MicroPython                                                              C++
```

- **目標**：驗證 [02 協定](02_通訊協定.md) 的 `\n`/`\r` byte 串流、末端讀指撥、`<位址>|<payload>\r` 收送。
- **做法**：中繼器週期性對末端（本地位址=4）發要求；末端回 `4|...\r`；中繼器印出解析結果。
- bus 兩端各 120Ω 終端 + 一處 failsafe 偏壓。
- **過關條件**：連續收送無錯、逾時（拔線）能被偵測。

## Stage 1 — 一台中繼器 + 多末端（單 bus multidrop）

```
[RP2040 中繼器] ══ RS485 bus ══╦══ [STM32 末端 #4  溫度]
                               ╠══ [STM32 末端 #5 壓力]
                               ╚══ [STM32 末端 #6]
```

- **目標**：round-robin 輪詢、cache dict、逾時跳過。
- **測試**：拔掉 #5 → 中繼器該格標 stale 並繼續輪詢其餘；插回 → 恢復 fresh。
- **過關條件**：cache 內容正確、單一節點失聯不卡住整條 bus。

## Stage 2 — 兩層樹（驗證分層位址 + cache 樹）

```
PC(Python) ══串列══ [RP2040 第1層中繼器 本地=1]
                          ║下層 bus
                 ╔════════╬═════════╗
        [RP2040 第2層中繼器 本地=32]  [STM32 末端 本地=5]
                 ║下層 bus
             [STM32 末端 本地=4]
```

- **目標**：
  - **逐跳前綴**：末端最終在 PC 端顯示為 `1-32-4`（深鏈已驗到 `1-2-3-7`）。
  - **上要下給**：PC 要資料時，第1層中繼器直接回 cache（不等下層跑完）。
  - PC 儀表板顯示樹狀 + 即時值 + 新鮮度。
- **過關條件**：位址字串正確拼出、PC 讀取速率與下層 bus 解耦（下層照跑、PC 隨要隨有）。

## Stage 3 — PC 規則引擎 +（可選）Ethernet 頂層

- PC 端做 [需求 17] 的**條件設定 → 自動控制**（例：某位址溫度 > 門檻 → 對某輸出位址下 `SET` 命令，需 ACK）。
- 若 Stage 2 觀察到 PC 端串列塞車，導入 **模組 F**：頂層改用 **RP2040 + W5500** 對 PC 走 Ethernet，對下層仍走 RS485。
- **過關條件**：大量節點下 PC 端不排隊、規則觸發延遲可接受。

## 建議工具

- **邏輯分析儀 / USB 轉 RS485**：直接掛 bus 上抓 `\n`/`\r` 框架，除錯最快。
- **兩顆 USB-TTL**：Stage 0 前可先不接 RS485，用 TTL 直連驗協定，再換上 MAX13487 驗實體層。
- **一致性測試向量**（來自模組 C）：三邊實作都跑同一組向量。
