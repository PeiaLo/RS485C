# 13 · PLC 模擬練習（銜接求職 × EASY IO）

> 2026-10-08 · 先全部用模擬，不買硬體。
> 目標職缺：**亞翔這類廠務／無塵室統包**（FMCS 廠務監控、PLC/SCADA 點位整合），或**能在公司內部導入 EASY IO 的職位**。

## 1. 先釐清角色：本專案接的是「PLC 外設」

```
客戶 PLC / SCADA / PC        ← 頂層（第 4 階段，介面尚未定案，見 12 風險表）
   │
中繼器樹（私有格式 0xFE）
   │
末端 STM32 ── 對下 Modbus master ──▶ 客戶的 PLC 外設（變頻器、溫控器、電表、壓差計…）
```

- **主線**：末端當 master 去讀**外設**。這和 PLC 工程師日常「用 Modbus 把外設接進 PLC」是同一件事，只是 master 換成 STM32。
- **練習順序**：先用 PLC 當 master 讀模擬外設（學會求職技能）→ 再把同樣流程搬進末端韌體（產品功能）→ 最後才練 PLC 讀頂層（第 4 階段）。

## 3. 模擬外設暫存器表

> 位址是 PDU 位址（0 起算）。手冊或 SCADA 若寫成 4xxxx，要自己換算，這是現場最常出錯的地方。

**unit 1 變頻器**（仿台達風格；實機請以手冊為準）

| 位址 | 名稱 | 讀寫 | 單位／說明 |
|---|---|---|---|
| 0x2000 | 命令 | RW | bit0-1：01=停、10=運轉；bit4-5：01=正轉、10=反轉（例：`0x0012`=正轉運轉） |
| 0x2001 | 頻率命令 | RW | 0.01 Hz，上限 6000；超過回例外 03 |
| 0x2100 | 錯誤碼 | R | |
| 0x2101 | 狀態 | R | bit0 運轉中、bit1 反轉、bit2 到達設定頻率 |
| 0x2102 | 頻率命令回讀 | R | 0.01 Hz |
| 0x2103 | 輸出頻率 | R | 0.01 Hz（加速 10 秒到 60Hz） |
| 0x2104 | 輸出電流 | R | 0.1 A |

**unit 2 溫控器 + 加熱爐**（變頻器帶的風扇轉越快，降溫越多）

| 位址 | 名稱 | 讀寫 | 單位／說明 |
|---|---|---|---|
| 0x1000 | PV 實際溫度 | R | 0.1 °C |
| 0x1001 | SV 設定溫度 | RW | 0.1 °C，上限 3000 |
| 0x1002 | 加熱輸出 | R | 0.1 % |
| 0x1003 | 運轉 | RW | 0=停、1=運轉 |
| 0x1004 | 高溫警報值 | RW | 0.1 °C |
| 0x1005 | 警報狀態 | R | bit0 高溫 |
| 0x1010 | P 比例增益 | RW | ×0.1（出廠 80 = 8.0） |
| 0x1011 | I 積分時間 | RW | 秒，0 = 關（出廠 0 → 純 P，會停在約 78°C） |
| 0x1012 | D 微分時間 | RW | ×0.1 秒，0 = 關 |

> 加熱到感測器有 3 秒延遲（dead time），P 調太大會震盪。

支援功能碼 03/04/06/16；例外碼 01（不支援的功能碼）、02（位址不存在或唯讀）、03（數值超範圍）。不存在的 unit 不回應。

## 4. 練習關卡

**A. 階梯圖基本功（GX Works / ISPSoft 模擬器）**
1. 啟停自保持、急停常閉
2. 正反轉互鎖
3. 計時器：延時啟動、Y-Δ 切換
4. 計數器：產品計數、批次停機
5. 警報閃爍 + 確認（ACK）+ 復歸，**廠務監控最常見的邏輯**

**B. PLC 當 master 讀模擬外設（CODESYS，先 TCP 再 RTU）**
1. 輪詢 PV/SV、輸出頻率/電流，換算成工程值（÷10、÷100）
2. HMI 或變數表下 SV、啟停溫控
3. 以 FC16 一次寫入「命令 + 頻率」，啟動風扇
4. **連鎖**：PV ≥ 警報值 → 風扇拉到 60Hz；回落後恢復；警報要 ACK
5. **通訊異常**：`--drop 0.2` 跑一次，做逾時、重試 3 次、斷線警報、數值標 stale（對應 EASY IO 的 stale 設計）
6. 換 RTU：com0com、9600 8E1；故意把 master 設成 8N1，觀察完全不通的樣子
7. 故意寫 70Hz、寫唯讀位址，在 PLC 端處理例外碼

**C. 搬進產品**
1. 把 B1–B5 的輪詢表寫成末端的外設 descriptor（見 [08](08_末端外設_Driver_韌性架構.md)）
2. 末端 STM32 透過 USB-RS485 接 com0com 的另一端，讀同一支模擬外設
3. 結果：**PLC 做得到的，EASY IO 末端也做得到**，這就是面試和內部導入的展示素材

## 5. 練習紀錄

### 2026-10-08 · QModMaster 手動關卡 ✅

| 遇到的狀況 | 現象 | 學到的事（面試可講） |
|---|---|---|
| 功能碼選 0x01 讀線圈 | 例外碼 01 | 變頻器、溫控器多半只支援暫存器（03/06/16） |
| Base Addr = 1 | 送出 0x0FFF，例外碼 02 | 位址偏移 1 是現場頭號錯誤；差一格有時讀到隔壁暫存器，數值看似合理 |
| Unit ID = 0 | 完全無回應、逾時 | 0 是廣播，外設照做但不回答；站號設錯時對方沒反應，不會報錯 |
| 模擬器重開 | `No error`、連線失效 | 外設重開機，master 不會自己重連 → PLC 程式要能偵測斷線並重連 |
| 寫 0x2001 = 7000 | `86 03` | 例外回應 = 功能碼 + 0x80；03 是數值問題，02 是位址問題 |
| 沒按 Enter 就送出 | 送出 `00 00`，寫入「成功」 | **寫完一定要讀回確認**（read-back） |
| 0x2000 讀到 17（0x0011） | 變頻器沒轉 | 命令字／狀態字：一個暫存器裡分成好幾個位元欄位 |
| 頻率 ÷100、電流 ÷10 | — | 點位表每個點都要寫清楚倍率 |
| 純 P 停在 78°C → I = 30 s 補到 80°C | — | P 控制有穩態誤差，I 用來補（使用者有蒸鍍機台 PID 調參經驗） |
| 風扇 60Hz，加熱輸出 100% 卡在 65°C | 怎麼調都上不去 | **輸出飽和**是設備能力不足，不是 PID 參數的問題；需要抗積分飽和 |
| 風扇降回 30Hz | 回到 80°C 且不超調 | 抗積分飽和的效果 |

下一關：CODESYS（B1–B7），改用 PLC 程式自動輪詢、做連鎖、處理逾時。

## 6. 對應亞翔類職缺要會講的

- **FMCS／點位表（I/O list）**：每個點的位址、型別、倍率、警報上下限、輪詢週期。§3 的暫存器表就是點位表的雛形。
- **廠務常見外設**：FFU 與排氣風扇（變頻器）、Chiller、溫濕度、**壓差**（無塵室正壓）、電力監控（電表）。下一步可以在模擬器加入壓差計和電表。
- **通訊**：Modbus RTU/TCP、4xxxx 位址換算、word order、例外碼、3.5 字元靜默、終端電阻／偏壓、單段 ≤32 節點。
- **可靠性**：逾時、重試、stale、看門狗、備援，正好對應 EASY IO「換一台、撥同一位址就恢復」的賣點。
