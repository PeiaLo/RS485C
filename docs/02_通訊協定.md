# 02 · 通訊協定

本文件是**各模組共用的契約**。建議先凍結此文件，再讓末端(Arduino)、中繼器(MicroPython)、PC(Python) 分頭實作。

## 1. 實體層

- **匯流排**：RS485 半雙工 2 線差動（A/B），multidrop，一條 bus 一個 master（該層中繼器）＋最多 64 slave。
- **中繼器 = 3 條獨立 bus / 3 顆收發器 / 3 UART**（架構定案見 [10 §1](10_自動終端與拓樸.md)）。下層依速度需求拆成兩條**彼此獨立**的 bus，不共線：

  | 埠 | 連到 | 角色 | IC 速度/邊緣 | 線長 |
  |---|---|---|---|---|
  | **UP（上層）** | 父層主幹 | slave | 高速・陡邊緣 | 短 |
  | **DOWN-trunk（下層主幹）** | 子中繼器 | master | 高速・陡邊緣 | 短 |
  | **DOWN-leaf（下層葉）** | 末端設備 | master | **低速・限斜率** | 長 |

- **收發器選型（依速度分流）**：
  - **中繼器上下骨幹（UP + DOWN-trunk）＝高速 485 IC**：中繼器↔中繼器（含↔PC）的高速轉發鏈路。
  - **中繼器↔末端（DOWN-leaf）＝低速 485 IC**：長葉段限斜率、抗 EMI／反射；與骨幹**獨立 bus**、不同速率。
  - **目前測試階段先用 MAX13487（AutoDirection，免 DE/RE GPIO，但需偏壓）過渡**；正式料號分流（高速件 vs 低速限斜率件）與「避免 AutoDirection、改手動 DE/RE」的最終定案見 [10 §6](10_自動終端與拓樸.md)。
- **Baud**：起步建議 **115200 8N1**（先求穩，之後量測後再往上調）。同一條 bus 全節點同 baud；但**骨幹 bus 與葉 bus 各自獨立設 baud**（骨幹高速、葉低速），非全樹同一 baud。
- **偏壓/終端**：每條 bus 兩端各一顆 120Ω 終端電阻；偏壓每條 bus **只放一組**（頭端），設備端一律不加。長葉段建議走 true fail-safe／可切換終端收發器免手動偏壓（見 [10 §4/§5](10_自動終端與拓樸.md)）。

## 2. 框架：byte 串流 + `\n` 未完 / `\r` 完成

資料以 **byte 為單位**串流。傳送端：

- 這段資料**還沒送完** → 該段結尾送 `\n`（0x0A）＝「還有，繼續等」。
- 整筆資料**送完了** → 結尾送 `\r`（0x0D）＝「這筆完整結束」。

接收端邏輯（**per-record emit，定版**：每遇 `\n`/`\r` 就吐出「一筆」記錄，並帶 `final` 旗標）：

```
buf = []
while True:
    b = read_byte()              # 逐 byte
    if b == '\n':                # 一筆完整、批次未完
        deliver(buf, final=False)   # 交出這一筆，後面還有
        buf = []
        continue
    if b == '\r':                # 一筆完整、批次結束
        deliver(buf, final=True)    # 交出最後一筆，這批收工
        buf = []
        return
    buf += b
```

> 白話：`\n` = 「這**一筆**完整了，但後面還有」；`\r` = 「這一筆完整了，而且整批到此為止」。
> 每一段（`\n` 或 `\r` 結尾）都是**一筆獨立記錄**——單筆回報就是一筆 `\r`；中繼器一次回一批孩子，就是多筆 `\n` + 最後一筆 `\r`（見 §3 末註）。此語意由 [共用協定庫 lib/](../lib/README.md) 的 `FrameDecoder` 保證，C++/Python 一致。

### 2.1 重要限制：payload 不能含裸 `\n` / `\r`

因為 `\n`/`\r` 被當成框架控制字元，**傳輸內容本身不可出現裸的 0x0A/0x0D**。做法：

- **JSON 一律單行（minified）**，不要 pretty-print。
- 若欄位值可能含換行，先做逃逸（`\\n`）或 base64。

（若日後 payload 必須含二進位，`\n`/`\r` 框架就不夠用，需改成「長度前綴」或 byte-stuffing——見 [06 設計決策](06_設計決策與待確認.md)。）

## 3. 傳輸內容格式（一筆完整資料）

一筆以 `\r` 收完的完整資料 = **完整分層位址 + 末端傳感器資訊**。建議格式：

```
<full-address>|<minified-json>\r
```

範例（單行）：

```
1-32-4|{"t":"TMP","v":26.7,"u":"C","ts":1723100000,"ok":1}\r
```

- `full-address`：字串路徑，如 `1-32-4`（逐跳前綴拼出，見 [03 §3](03_定址與指撥開關.md)）。
- `json`：該末端的量測 payload（型別、值、單位、時戳、狀態）。schema 見 [schema/](../schema)。

> 分段（未完 `\n`）可以用在「一台中繼器要一次回一批孩子」時：每個孩子一行以 `\n` 結尾，最後一行以 `\r` 收尾，代表這批回完。

### 3.1 編碼定案（2026-09-16）：第一 byte 判別 · MODBUS 對外 · 私有格式對內

**核心：每個 frame 的第一個 byte 就是「用哪個解析器」的判別。** 以此統一 MODBUS（對外互通）與私有格式（樹內高速）。

| 第一 byte | 意義 | 框架 | 用在 | CRC |
|---|---|---|---|---|
| **`0x01`–`0x3F`（1–63）** | 一般 MODBUS 定址（本地 slave 位址） | MODBUS RTU（3.5 字元靜默） | **末端兩側**（↔外部外設、↔中繼器） | MODBUS CRC-16（幀尾 2 byte） |
| **`0xFF`** | **MODBUS 廣播** | MODBUS RTU | 對整條 bus 全體下令 | MODBUS CRC-16 |
| **`0xFE`** | **私有格式** | `…[*<crc16>]\r` | **中繼器 ↔ 中繼器骨幹（含 ↔PC）**；亦可在任一 bus 承載 JSON | **可選**（`*<crc>` 槽預留、預設關；開則 `\r` 前驗） |

> `0x00` 空出（MODBUS 標準廣播已改用 `0xFF`）；`0x40`–`0xFD` 保留。

**分工（2026-09-16 定案，蓋掉先前「整棵樹走私有」）——MODBUS 在末端兩側(edge)、私有格式只在中繼器骨幹(core)**：
- **末端 ↔ 外部外設（尾段 adapter，可插拔）**：**末端＝master**，預設 **MODBUS RTU** 讀外部 PLC 感測/驅動模組（**bus 速率 115200**）；**MODBUS 是預設 driver，不是唯一**——尾段留協定介面，日後可加其他 fieldbus/感測協定（[06 §O](06_設計決策與待確認.md)）。外設**不進樹狀定址**——末端 MCU 抓值後放進本地 cache，靠 **JSON descriptor** 定義「怎麼抓」（[08 §6](08_末端外設_Driver_韌性架構.md)）。
- **末端 ↔ 中繼器（葉上行）**：**中繼器＝MODBUS master、末端＝slave**。末端把 cache 的聚合值以 **MODBUS 暫存器**呈現給中繼器輪詢（任何標準 MODBUS master／PLC 也能在葉層接進來讀）。
- **JSON descriptor 定義「末端怎麼抓每個外設」**（regtype/addr/fc/dtype/word_order/scale 綁定，見 [08 §6/§7](08_末端外設_Driver_韌性架構.md)）。
- **中繼器 ↔ 中繼器（骨幹，含 ↔PC）**：走 `0xFE` **私有格式**、**高速 RS485**。**第一台中繼器**把末端的 MODBUS 讀值**轉成私有格式**、開始逐跳前綴 path。外設多時 cache 量大 → 骨幹要高速。

**私有格式 frame（`0xFE`，骨幹）**：
```
0xFE 1-2-3-7|25.1,3.2,1013*A3F1\r
     └ path ┘└ 值(descriptor 定順序) ┘└CRC┘
```
- path **只到末端節點**（不含外設段）；payload = descriptor 定序的值（CSV）或 JSON。
- **CRC＝可選（初期不設、後可加、不影響硬體）**：框架**保留** `*<crc>` 槽與 `crc16()`，但 **`CRC_ENABLED` 預設 False**（先求跑通）。要開時只動協定庫、設 True、以 `test_vectors.json` 對齊——**純軟體、硬體架構不變**。開啟後語意：CRC-16/MODBUS，**`\r` 前檢查**、驗不過丟棄 → stale、**逐跳重算**。（對真實外部 MODBUS 設備，MODBUS 幀本身含 CRC，由尾段 driver 處理，一樣是軟體。）

**JSON 只用兩處**（皆包在 `0xFE` 私有格式內）：
1. **首次連接**：node 自描述 DESC（身分 + `peripherals[]` + 每個外設的 MODBUS 抓取方式）。
2. **定期存活檢查**：每 **10 秒**一次，確認 node 仍在線（與框架外健康 envelope `ok`/`up`/`rst` 互補）。

- **`age` + 健康 envelope 放框架外** → 中繼器純轉發、不碰 payload、免 age 疊層。
- **指標式組裝**：末端按 descriptor 順序**指向各外設 cache 槽**串出 payload，免中間 JSON 物件（見 [09 §4](09_軟體架構定案.md)）。
- 詳細軟體架構定案見 [09](09_軟體架構定案.md)；MODBUS 綁定見 [08](08_末端外設_Driver_韌性架構.md)。

### 3.2 核心格式原則 ＋ 量測 payload 定案（2026-11-01）

**原則：canonical 核心 + 邊界 adapter** —— **中間 backbone 永遠用「我們選的格式」；頭尾不管外界是什麼，都在邊界 adapter 轉入/轉出。**
→ **安全**（核心受控、外界格式變化擋在邊界、中繼器只碰自家格式）· **準確**（descriptor 單一真相 + CRC 逐跳）· **效率**（核心精簡、中繼器零轉譯）。

```
外界A(MODBUS) ─┤末端 adapter├─▶ 【核心：我們的文字格式】 ─┤PC adapter├─▶ 外界B(消費端要的任何格式)
```

| 段 | 格式 | adapter |
|---|---|---|
| 末端 ↔ 外設 | **MODBUS** | 末端讀外設（**我讀 PLC**）|
| 末端 → 中繼器 → PC（**核心**）| **我們的文字格式** | 中繼器純前綴 path + 重算 CRC、**不轉譯** |
| PC → 消費端 | 隨消費端（JSON / 表格 / MODBUS gateway）| PC 轉出 |

**轉譯盤點**：末端 cache→文字（×1）＋ PC 文字→使用者格式（×1）；**中繼器 0**。（末端直接吐文字 → 轉入在末端，不在中繼器。）

**② 量測資料格式（核心，可替換、換了不動架構/中繼器）**：

| 格式 | 範例 | ~byte | 看得懂 |
|---|---|---|---|
| **JSON** | `{"temp":25.1,"pres":3.2,"alt":1013}` | ~40 | ◎ 自描述、最熟悉 |
| KV | `temp=25.1;pres=3.2;alt=1013` | ~19 | ◎ 自描述、省一半 |
| CSV | `25.1,3.2,1013` | ~13 | ✗ 要對 descriptor |

- **✅ 定案：核心先用 JSON** —— 看得懂（自己 + 師父 + 教學 + sniff bus）、**零改動**（= proven 3R3T）。
- **提速後路：KV**（`key=val`，自描述 + 省一半）。**要加速時換 KV**；CSV 為極限密度、再議。
- **換格式只動「末端吐法 + PC 解析」，中繼器一行不改** → 不怕選錯、隨時可換。
- ⏱ **提速時機（Claude 會主動提醒）**：backbone 每輪總 byte 逼近 baud 預算、或 soak 見吞吐天花板、或節點×外設增多使更新週期拉長 → 換 KV。可用 [../sim/capacity.py](../sim/capacity.py) 估。
- 二進位（length-prefix）最密但不可讀、resync 難、要改框架 → **不採用**；保留第一 byte 旗標後路；純速度另靠**拉 baud**。

## 4. 輪詢時序與逾時（中繼器行為）

以第 1 層中繼器為例（[需求 14、15]）：

```mermaid
flowchart TD
    A[開始：指向下層第 1 個設備] --> B[對該設備發要求]
    B --> C{在 timeout 內收到 \\r ?}
    C -- 是 --> D[存進 cache 該設備欄位<br/>標記 fresh + 時戳]
    C -- 否 逾時 --> E[標記 stale / 不可用<br/>跳過]
    D --> F{PC 是否有要求資料?}
    E --> F
    F -- 有 --> G[把 cache 回給上層]
    F -- 沒有 --> H[指向下一個設備]
    G --> H
    H --> A
```

要點：

1. **round-robin**：問完一個孩子（收到 `\r` 或逾時），就回頭看上層有沒有要，再問下一個。
2. **逾時就跳過**：等 `\r` 期間逾時 → 不卡住，標記該孩子 stale，換下一個。逾時值建議可調（依 baud 與最大 payload 估）。
3. **上層要求優先權**：上層一要，優先回 cache，不必等當前輪詢跑完一圈。

## 5. 請求 / 回應方向

- **PC → 第1層中繼器**：要資料（可「要全部 cache」或「要指定位址」）。
- **中繼器 → 下層**：主動輪詢（master）。
- **下層 → 中繼器**：被問才回（slave）。
- 中繼器對上層也是 slave：**平時不主動推**，被要求才回 cache。

## 6. 進階（編輯）模式 — 軟體指令（DIP 已拿掉）

原「DIP 功能位 OFF＝進階」隨自動定址一起改為**軟體指令切換**（見 [03 §2](03_定址與指撥開關.md)、[06 §O](06_設計決策與待確認.md)）：上層用位址精準指定某台，送 `CFG|<addr>|<json>\r` 令其進設定模式、接受寫入（更新自有 JSON descriptor、校正、參數）。常規模式只做讀取/回報。呼應記憶 `firmware-soft-reset`「無實體腳、軟體指令（位址 N → CFG / 重開）+ 看門狗」。

## 7. 待確認事項（彙整於 06）

- 廣播機制。→ ✅ 已定：**節點位址 0 保留**（自動定址從 1 起、不發 0）；**MODBUS 外設 bus 廣播＝第一 byte `0xFF`**（見 §3.1）。兩者不同層。定址改**自動定址（ENUM 枚舉）、DIP 拿掉**（見 [03](03_定址與指撥開關.md)、[10 §8](10_自動終端與拓樸.md)、[06 §O](06_設計決策與待確認.md)）。
- 框架。→ ✅ 已定：私有格式（`0xFE`）用 `…*<crc>\r`；MODBUS（1–63/`0xFF`）用原生 RTU 靜默框架（見 §3.1）。
- 是否需要 CRC/checksum。→ **可選**：初期不設（`CRC_ENABLED=False`），`*<crc>` 槽與 `crc16()` 預留，後可加、**不影響硬體**（見 §3.1）。
- 上層「要指定位址」的請求語法。→ `REQ|<addr|ALL>`（位址到**節點**；外設由該節點 cache 提供）；動詞 DESC/REQ/SET 見 [09](09_軟體架構定案.md)。
- 外設定址。→ ✅ 已定：**外設不進樹狀定址**，由末端 MCU 抓取(MODBUS@115200)+cache，descriptor 定索引與抓取方式（見 [08](08_末端外設_Driver_韌性架構.md)、[06 §N](06_設計決策與待確認.md)）。
