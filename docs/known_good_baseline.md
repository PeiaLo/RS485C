# RS485_C 已知良好基準（Known-Good Baseline）

**用途**：日後任何時候懷疑退化，跟這個比對。長得像＝正常；長不像＝哪裡壞了。

---

## 基準日期：2026-09-04（下層 RS485 首次乾淨跑通）

**配置**：
- 好品質麵包板
- **每條 bus：2×120Ω 終端（兩端各一，跨 A-B）+ 1 組偏壓 560Ω（A→5V、B→GND，全 bus 一處）**
- USB-485 模組**內建偏壓** → Bus1 不外加偏壓
- 中繼器 Nucleo(COM8)：上層 USART6(PC6/PC7)+MAX1、下層 USART1(PA9/PA10)+MAX2
- 末端4 DevEBox(COM9)：Serial1(PA9/PA10)+MAX3，addr 4

## 乾淨的樣子（截自實測 monitor）

```
探針   │ 1-4|{"t":"TMP","v":28.0,"u":"C","ok":1,"up":31,"rst":"bor","age":84}
中繼器 │ [repeater] up_rx=483 down_rx=9230 frames=407 last="REQ|5"  cache[0]=1-4 fresh
末端4  │ [terminal] replied: 4|{"t":"TMP","v":28.0,"u":"C","ok":1,"up":31,"rst":"bor"}
末端4  │ [terminal] rx: 4|{"t":"TMP","v":28.0,"u":"C","ok":1,"up":31,"r   ← 自己回覆的自我回音(乾淨)
```

## 「正常」判準（逐項對照）

| 看哪裡 | 正常 | 壞掉的樣子 |
|---|---|---|
| 探針收到的 JSON | **乾淨** `1-4|{...}` | `#ok`/`rs|`/`ok>` 等**位元錯誤** = 反射/終端/偏壓數量錯 |
| 探針的 `age` | **小**（幾十~幾百 ms）、一直變 | 一直**變大、值凍住不動** = 化石 stale，其實沒在收新資料 |
| 探針的 `v` 值 | **即時跳動** | 凍住 = 同上 |
| 中繼器 `cache[0]` | **`1-4 fresh`** | `(空)`=沒收到；`stale`=收過但現在收不到 |
| 中繼器 `down_rx` | **快速漲**（含回覆，>~200/s） | 只 +~36/s（≈純 REQ 回音）= 收不到回覆 |
| 中繼器 `last=` | 乾淨 `4|{...}` | `"REQ|x"`（只聽到自己回音）或含 `�`（污染） |
| 中繼器 `down_rx/frames` | **>>6**（有完整長回覆） | ≈6 = 每幀都是 6-byte REQ 回音、零回覆 |
| 末端 `rxBytes` | **一直漲** | 凍住 = 沒收到 REQ（上游沒發/斷線） |
| 末端 `rx:` 內容 | 乾淨 `REQ|4` / 自我回音 | `��REQ`（前面一堆 `�`）= idle 浮動亂吐 = 偏壓沒定住 |

## 一鍵重現指令
```
python rs485_monitor.py COM8:中繼器 COM9:末端4 COM10:探針:PROBE:4
```
（COM 依實際；探針那顆是 USB-485）

## 黃金法則（電阻數量，踩過最久的坑）
**每條 bus = 2×120Ω（兩端）+ 1 組偏壓（2×560Ω，全 bus 一處）= 共 4 顆。多了少了都錯。**
- 120Ω 一顆 → 另一端反射；每顆都放 → 過載推不動
- 偏壓沒有 → idle 浮動亂吐；每顆/每 bus 重複 → 過重拉歪 idle
- USB-485 內建偏壓 → 該 bus 不外加
