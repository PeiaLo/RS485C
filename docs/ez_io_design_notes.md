# EZ_IO 設計共識整理

> 更新：2026-11-01（名稱定為 **EZ_IO**；衝突與定案見文末「與 v2 定案對齊」）

## 定位

- 從客戶電腦到末端感測器，中間的傳輸全部由 eastio 負責，不限頭尾廠牌，也不限數量
- 借用 CPO（Co-Packaged Optics）的概念：轉換只發生在兩端，中間只跑一種格式
- 主要痛點鎖定在**擴充**
- 擴充一律由我方執行，不交給客戶。商業模式是「產品 + 擴充服務」

## 架構

- 核心節點 + 末端擴充板
- 訊號種類的支援靠擴充板與客製韌體，而非先天硬體限制
- 每台一進一出，以菊花鏈串接（RS485）
- 控制規則放在電腦端軟體，與硬體分開（**PC＝監督規則**；**末端走快迴路/本地閉環**，見 [06 §I](06_設計決策與待確認.md)）
- 擴充板之間也要用不需配線的方式連接，以節省空間

## 設定與維運

- 以 JSON 描述每個節點：連接對象、功能都預先寫好
- 安裝後共同完成第一次調適，之後更換只需插拔
- 末端自動偵測、故障定位：屬於初始設定功能（已具備）
- **編號以身分決定，不依物理位置**（擴充後 23 號旁邊可以是 31 號）→ **定案：一律以 JSON 為主**；ENUM/自動定址退為「探索 + 自動終端 + 位置輔助」，不再是編號來源（refine [06 §O-2](06_設計決策與待確認.md)、[03](03_定址與指撥開關.md)、[10 §8](10_自動終端與拓樸.md)）
- 斷線時的數值替換：依客戶需求，針對特定位址寫入

## 對客戶端

- 交給客戶電腦的資料，要轉成客戶既有系統（SCADA/HMI）看得懂的格式

## 資產

- 建立每個廠商的設備 map 庫（通訊參數、暫存器表、資料型態、byte/word 順序、比例換算、單位、韌體版本）

## 外觀與標示

- **電子紙（優先）**：顯示編號等資訊，斷電後仍保留畫面，可以簡單修改
- **雷雕序號並存**：即使有電子紙，仍可保留雷雕序號
- 狀態燈

## 資安（參考 [Dungle_ATTINY402.ino](Dungle_ATTINY402.ino)）

- 目前最弱的一環 → 走**挑戰-回應認證 dongle**（硬體防仿冒/真品驗證）。
- 機制：host 送 13-byte 挑戰 `[0xA5][0x5A][key_sel][10B 亂數]`；dongle（ATTINY402）用**密鑰表 + 自訂 keyed CRC32** 算出、回 **4-byte** 回應。直連 UART、9600 8N1、無 bus ID。
- 每個 dongle 有專屬 10 組密鑰表（與其他模組不同），`key_sel` 選用哪把。

## 仍未定案（擴充板：先記著，之後再定）
